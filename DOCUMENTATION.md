# Denim Tracker — Invoice Generator

A single-page invoice generator built with **plain HTML, CSS, and JavaScript** — no
libraries, no frameworks, no build step. It reproduces the layout of the original
printed "DENIM TRACKER" GST bill and calculates all amounts automatically as data
is typed.

Open `index.html` in any modern browser (Chrome, Edge, Firefox) — nothing needs
to be installed or served; it works straight from the file system.

(html2canvas + jsPDF in one file), stored **locally** so the Download PDF

## 2. File descriptions

### `index.html`

One page containing, in order:

| Section (CSS class)   | Purpose                                                                  |
|-----------------------|--------------------------------------------------------------------------|
| `.toolbar` (`no-print`) | Screen-only controls: **Add Row**, **Print**, **Download PDF**, **Reset Invoice** |
| `#imageInput`         | A single hidden `<input type="file">` reused for every image replacement |
| `.invoice`            | The A4-style invoice sheet itself                                        |
| `.inv-header`         | One full-width changeable header image (company name, address, emblem, logo all live inside that image) |
| `.header-bar`         | The thick black divider bar under the header                             |
| `.bill-to`            | Buyer details (M/S., address, GSTIN) and Bill no / Date box              |
| `.items-table`        | The line-item table (NO / Particulars / Quantity / Rate per / Amount)     |
| `.inv-bottom`         | Bank details box (left) + totals block (right)                           |
| `.inv-footer`         | Payment terms, HSN code, "For, DENIM TRACKER" signature + colour strip   |

Two attribute conventions drive all the JavaScript:

- **`data-field="name"`** on a `contenteditable` element marks a named, editable,
  auto-saved text field (e.g. `companyName`, `billNo`, `date`, `sgstRate`).
- **`class="changeable" data-image="name"`** on an `<img>` marks a replaceable
  image (`logo`, `emblem`, `bank`). Clicking it opens a file picker.

The item-table rows are **not** in the HTML — they are generated by
`js/script.js` (see §4).

### `css/style.css`

Organised into numbered sections (the file has a matching table of contents
comment at the top):

1. **Design tokens & base** — the `@font-face` for **Oswald** (a variable
   font loaded locally from `assets/fonts/`, so the page works offline; it
   covers weights 200-700, giving true bold rendering — a single-weight
   font here would get blurry synthetic bold. First choice in the
   `--font-invoice` stack, applies to all invoice text), CSS custom
   properties (`--ink`, `--navy`, border widths), and the page background.
2. **Toolbar** — the screen-only button bar.
3. **Invoice sheet** — the white 820 px "paper" card.
4. **Header** — flex row: company block, emblem, logo box; plus the black bar.
5. **Buyer / bill meta** — the bordered two-column box.
6. **Items table** — column widths via `<colgroup>` classes (`.w-no` 8 %,
   `.w-part` 44 %, `.w-qty` 14 %, `.w-rate` 14 %, `.w-amount` 20 %); heavy
   black borders on all cell edges (matching the printed bill) and large bold
   19 px cell text; transparent `.row-input` inputs that blend into the
   cells; hover-only `.row-delete` button.
7. **Bank + totals** — flex split (bank box left, 4-row totals grid right).
8. **Footer** — terms, HSN, signature block with the CSS-gradient colour strip.
9. **Editable affordances** — yellow hover/focus tint on `contenteditable`
   fields, dashed outline on hoverable images. Screen only.
10. **Print rules** — `@page { size: A4 }`, hides `.no-print` and delete
    buttons, removes the shadow/tints, and uses `print-color-adjust: exact` so
    the black bar and colour strip actually print.

### `js/script.js`

A single IIFE (`(function () { ... })()`) — nothing leaks into the global
scope. Written in plain ES5-compatible style. Sections:

1. **Constants & references** — `STORAGE_KEY`, `MIN_ROWS = 16` (blank rows so
   the sheet looks like the full printed page), `SAVE_DELAY_MS = 300`.
2. **Row management** — `createRow(data)`, `addRow()`, `buildRows(rows)`.
3. **Calculations & formatting** — `toNumber()`, `formatINR()`, `getRate()`,
   `recalc()` (see §3 below).
4. **Image replacement** — `wireImages()` (see §5).
5. **Persistence** — `collectState()`, `save()`, `scheduleSave()` (debounced),
   `applyState()`, `load()` (see §6).
6. **Toolbar & event wiring** — `wireEvents()`, `todayString()`.
7. **Init** — restore or build fresh, wire everything, first `recalc()`.

### `assets/*.svg`

Simple hand-written placeholder graphics. They are **defaults only** — the user
replaces them by clicking the image on the page (the replacement is stored in
the browser, the SVG files themselves are never modified).

## 3. Calculation logic

All calculations live in one function: **`recalc()`** in `js/script.js`. It is
called on **every** `input` event anywhere in the document (one delegated
listener), so the sheet is always up to date.

Per row:

```
amount = quantity × rate
```

- Inputs are parsed with `toNumber()`, which strips commas/spaces
  (`"2,000"` → `2000`) and treats anything non-numeric as `0`.
- A row's amount cell is left blank when the product is 0.
- The **NO** column is auto-numbered: rows containing any data (particulars,
  qty, or rate) get sequential serial numbers; empty rows stay blank.

Totals:

```
totalBeforeTax = Σ (all row amounts)
sgst           = totalBeforeTax × sgstRate / 100     (default rate: 2.5)
cgst           = totalBeforeTax × cgstRate / 100     (default rate: 2.5)
totalAfterTax  = totalBeforeTax + sgst + cgst
```

- The tax percentages themselves are **editable on the sheet** — the `2.5` in
  "SGST@ 2.5%" / "CGST@ 2.5%" is a `contenteditable` span
  (`data-field="sgstRate"` / `"cgstRate"`). Change it and everything recomputes.
- Display formatting uses `formatINR()` → `Number.toLocaleString('en-IN')`,
  giving Indian digit grouping (`1,30,000`) with paise shown only when the
  value isn't a whole rupee (max 2 decimal places).

Worked example (matches the reference bill): qty `2000` × rate `15` =
`30,000`; SGST 2.5 % = `750`; CGST 2.5 % = `750`; total after tax = `31,500`.

## 4. Item rows

- On a fresh start `buildRows([])` renders **16 blank rows** (`MIN_ROWS`) so the
  invoice fills the page like the paper original.
- **Add Row** (toolbar) appends one more row and focuses its particulars cell.
- Hovering a row shows a red **×** button just outside the right edge of the
  table; clicking it deletes that row (the last remaining row can't be
  deleted). The button carries `no-print` styling, so it never prints.
- Each row is a `<tr>` produced by `createRow()`:
  - `td.col-no` — serial number (auto-filled by `recalc()`, not editable)
  - three `<input class="row-input">` cells with `data-col` =
    `particulars` / `qty` / `rate`
  - `td.col-amount` — computed `<span class="amount">` + delete button

To change the default number of blank rows, edit `MIN_ROWS` at the top of
`js/script.js`.

## 5. Changeable images

Two images are replaceable. Each is an `<img class="changeable">` with a
unique `data-image` key:

| Key      | Where on the invoice                             | Default file           |
|----------|--------------------------------------------------|-------------------------|
| `header` | The entire header band (full width of the sheet) | `assets/header.svg`     |
| `bank`   | Bottom-left (bank box)                           | `assets/bank-logo.svg`  |

Flow (`wireImages()` in `js/script.js`):

1. Clicking a changeable image stores it as `imageTarget` and clicks the
   hidden shared `#imageInput` file picker.
2. On file selection, a `FileReader` reads the file as a **data URL** and
   assigns it to the image's `src`.
3. Because the `src` now starts with `data:`, `collectState()` includes it in
   the saved state — so the replaced image **survives page reloads**.
4. Only images the user uploaded are saved (each upload sets a `userSet`
   flag); the files in `assets/` are never touched.

**Default images are embedded as data URLs.** On page load,
`applyDefaultImages()` (in `script.js`) swaps each changeable image's file
`src` for the base64 copy in `js/default-images.js`. Reason: when
`index.html` is opened directly from the file system (`file://`), Chrome
treats image *files* as foreign origins — they "taint" the canvas that the
Download PDF button renders, and the export fails with a SecurityError.
Data-URL images can never taint the canvas, so the export works everywhere.

If you change a default image file in `assets/`, regenerate its entry in
`js/default-images.js` (PowerShell):

```powershell
[Convert]::ToBase64String([IO.File]::ReadAllBytes("assets\header-logo.png"))
```

…and paste the output into the matching `data:image/png;base64,...` string.

To add another changeable image, just add
`class="changeable" data-image="someUniqueKey"` to any `<img>` in
`index.html` — no JS changes needed.

## 6. Data persistence (auto-save)

Everything the user types or uploads is auto-saved to
**`localStorage`** under the key `denim-tracker-invoice-v1`.

- Saving is debounced (300 ms after the last keystroke) via `scheduleSave()`.
- The saved snapshot (`collectState()`) has three parts:

```json
{
  "fields": { "companyName": "...", "billNo": "...", "sgstRate": "2.5", ... },
  "rows":   [ { "particulars": "EMB WORK ...", "qty": "2000", "rate": "15" }, ... ],
  "images": { "logo": "data:image/png;base64,..." }
}
```

- On load, `load()` → `applyState()` restores fields, rebuilds rows, and
  re-applies uploaded images. If nothing is saved (first visit), the page
  starts with the default Denim Tracker details, 16 blank rows, and today's
  date in `dd-mm-yyyy` format.
- **Reset Invoice** (toolbar) clears the storage key and reloads the page
  after a confirmation dialog.
- Very large uploaded images can exceed the localStorage quota (~5 MB); the
  `save()` call is wrapped in `try/catch` and logs a console warning instead
  of crashing. Use reasonably sized images.

Note: data is stored **per browser, per machine**. It is not a database — for
multiple saved invoices, that would be a future feature (see §9).

## 7. Printing & PDF export

Two toolbar buttons produce paper/PDF output:

**Download PDF** — one-click PDF file. `downloadPdf()` in `js/script.js` uses
the locally bundled **html2pdf.js** (`assets/vendor/html2pdf.bundle.min.js`,
loaded via a `<script>` tag before `script.js`):

- The sheet (`#invoice`) is rendered to canvas (scale 2) and placed on
  **exactly one** A4 portrait page, scaled to fit within 8 mm margins and
  centred horizontally. (html2pdf's built-in paginator is bypassed — it
  splits by CSS pixel height and would cut the sheet onto a second page;
  instead the code takes the worker's canvas, deletes the auto-generated
  pages, and adds the image itself.)
- The file is named from the bill number, e.g. `Invoice-01.pdf`.
- During capture the `exporting-pdf` class on `<body>` hides screen-only
  elements (row-delete buttons).
- If the library file is missing or export fails, an alert points the user to
  the Print button as a fallback. Note the output is an image-based PDF
  (text is not selectable); use Print → "Save as PDF" for a vector PDF.

**Print** — calls `window.print()`; choose "Save as PDF" as the printer to get
a vector PDF. This path also always outputs **one page**: `beforeprint` /
`afterprint` handlers in `script.js` (`fitSheetForPrint()`) apply a computed
`zoom` on `#invoice` so the sheet shrinks to the A4 printable area
(~733 × 1062 px at 96 dpi with the 8 mm margins). This covers the Print
button, Ctrl+P, and the browser menu alike. The print stylesheet (section 10
of `style.css`) keeps the sheet at its 820 px screen layout so the zoom math
holds, and additionally:

- sets `@page { size: A4; margin: 8mm }`;
- hides the toolbar and the row-delete buttons (`.no-print`);
- removes the drop shadow, page background, and editing hover tints;
- forces the black header bar and the footer colour strip to print via
  `print-color-adjust: exact`.

To get a PDF, choose **"Save as PDF"** as the printer in the browser dialog.

## 8. Editing conventions (important when making changes)

These are the rules the code relies on — keep them intact when modifying:

1. **Named text fields**: any element with `data-field="x"` is editable and
   auto-saved by that name. Field names must be **unique**. Multi-line fields
   (addresses, terms, bank details) rely on `white-space: pre-line` in CSS to
   preserve line breaks stored via `innerText`.
2. **Row inputs**: must keep `class="row-input"` and their `data-col`
   attributes — `recalc()` and `collectState()` query by these.
3. **Totals elements**: `#totalBeforeTax`, `#sgstAmount`, `#cgstAmount`,
   `#totalAfterTax` are written by `recalc()` — don't rename without updating
   `script.js`.
4. **One delegated `input` listener** on `document` handles recalculation and
   saving for *everything* — new editable elements need no extra wiring.
5. **`no-print` class**: put it on anything that must not appear on the
   printed invoice.
6. **Storage versioning**: if you change the *shape* of the saved state, bump
   `STORAGE_KEY` (e.g. `...-v2`) so stale saved data doesn't break loading.
7. Plain JS only (ES5-style, single IIFE), no external fonts/CDNs — the page
   must keep working offline from the file system.

## 9. Ideas for future features

Not implemented, but the codebase is structured to accept them easily:

- **Multiple saved invoices** — store an array of state snapshots keyed by
  bill number; add a picker in the toolbar.
- **Amount in words** — add a `numberToWords()` helper and a footer line fed
  from `recalc()`.
- **IGST mode** — a toggle that swaps the SGST/CGST rows for a single IGST row
  (adjust the `.totals` markup and `recalc()`).
- **Export/import JSON** — `collectState()` / `applyState()` already do the
  work; just add download/upload buttons.
- **Round-off row** — round `totalAfterTax` to the nearest rupee and show the
  difference as a "Round off" totals row.
